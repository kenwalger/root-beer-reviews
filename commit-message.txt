Fix root beer update route to accept form data

Fixed the update_rootbeer route to properly handle form-encoded data from
the HTML form instead of expecting JSON. The route was previously using a
Pydantic model which FastAPI parsed from JSON, but the admin form submits
form-encoded data.

## Changes

- Updated `update_rootbeer` route in `app/routes/admin.py` to accept
  individual `Form(...)` parameters instead of `RootBeerUpdate` model
- Matches the pattern used in `create_rootbeer` route for consistency
- All fields are optional to support partial updates
- Removed unused `RootBeerUpdate` import

## Test Updates

- Updated `test_update_rootbeer_success` to use form data (`data={...}`)
  instead of JSON (`json={...}`)

## Bug Fix

This resolves the error users encountered when trying to update root beer
notes or other fields via the admin interface:

```
{"detail":[{"type":"model_attributes_type","loc":["body"],
"msg":"Input should be a valid dictionary or object to extract fields from",
"input":"name=..."}]}
```

The form now correctly submits and updates root beer data as expected.
